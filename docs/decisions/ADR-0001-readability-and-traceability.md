# ADR-0001：可读性与可溯源性（Readability and Traceability）

- **状态**：Accepted
- **日期**：2026-10-16
- **相关 ADR**：本文件是文档契约的总纲；具体技术决策见 ADR-0002 ~ ADR-0016

## 背景（Context）

需求要求「外观、配置、主题与核心逻辑分开」「模块与文件职责尽量单一」「注重 Ubiquitous Language」。
补充约束进一步要求：每个文件有文件头（模块名/职责/依赖/被依赖/相关 ADR）、每个公开函数有 docstring
（前置条件/后置条件/禁止/异常）、注释只解释「为什么」、不得有死代码与无条件 TODO；
并且每个关键决策要能在「为什么这么定」与「在哪儿实现」之间双向查到。

约束如果只靠自觉遵守，会在第三次改动时退化——特别是本项目有 3 个输出语义各异的 llama 工具、
一次运行跨 4 个进程/线程，靠记忆维持边界是不现实的。

## 决策（Decision）

把可读性与可溯源性做成**可机械校验的契约**，而不是文档里的道德要求：

1. **文件头契约**：每个 `.py` 模块头必须含「模块名 / 职责 / 依赖 / 被依赖 / 相关 ADR」五个字段。
2. **函数契约**：每个公开函数与方法（含 `@property`、`classmethod`、`staticmethod`，
   即名字不以 `_` 开头者）的 docstring 必须含「前置条件 / 后置条件 / 禁止 / 异常」四节。
   私有方法与 dunder（如 `__init__`）不强制四节——它们的契约由宿主类的公开接口承载。
3. **ADR 双向引用**：代码的「相关 ADR」写 ADR 文件名；每个 ADR 的「相关代码位置」写
   `路径::符号`。两者的交集必须非空——既不允许悬空 ADR，也不允许悬空引用。
4. **静态自检**：`tools/check_traceability.py` 机械执行上述 1~3 条，外加「无 TODO/FIXME」
   与「ADR 编号连续无缺号」，失败即以非零码退出。
5. **注释纪律**：行内注释写「为什么」（如「500 是**字节**上限，长中文试卷必然走截断分支」），
   不写「做什么」（代码已表达）。

## 理由（Rationale）

- 契约一旦可被 `python3 tools/check_traceability.py` 判定，回归就会在提交前暴露，而不是在评审时靠人眼。
- 「为什么」写在 docstring 与 ADR 里，「在哪」写在 `路径::符号`，两个方向都能从文件系统直接跳转，
  不需要额外工具链（无 Sphinx、无文档站）。
- 沿用 Python 既有能力：`ast` 解析 + `pathlib` 遍历 + `re` 匹配，零依赖。

## 后果（Consequences）

- 写代码变慢：每个新公开函数要多写四行契约；每个新决策要多写一份 ADR。
- 换来的是：新人（或下一个会话）能在不读实现的前提下知道「这个模块管什么、不许干什么、
  为什么这里要重试而那里不许重试」；`--headless` 产出的数字能从 JSONL 一路查到原始 stdout。
- 反面代价：契约是文本匹配，存在「写了但没意义」的空话风险（如把「异常: 无」当占位符）。
  这是被接受的：它至少强制作者对「是否真的无异常」做出判断。
