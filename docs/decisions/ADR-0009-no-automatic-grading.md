# ADR-0009：本阶段不自动判分

- **状态**：Accepted
- **日期**：2026-10-16
- **相关 ADR**：ADR-0005（答卷落盘）、ADR-0011（答卷吞吐）

## 背景（Context）

需求原文：让模型「回答本地的测试卷子，输出答案文件」；对结果的描述是
「基于问卷的结果则输出一份文件」。**没有**要求打分或排名。

试卷内容（`test_content/real_test/paper_1`）包含知识问答、反注入、知识边界等题型，
答案以自然语言为主——判分需要标准答案或评分标准。

候选方案：
1. 引入 LLM-as-judge（再调一次模型给分）；
2. 内置正则/关键词匹配判分；
3. 人工评分表；
4. **不判分，只落盘答卷 + 吞吐**。

## 决策（Decision）

本阶段**不自动判分**。`AnswerSheet` 只承载：试卷名、模型名、答案正文、prompt 吞吐、
generation 吞吐、墙钟耗时；写成 Markdown 文件（含元数据头）供人阅读。

**2026-10-17 复确认**：在"是否要自动判分（LLM-as-judge / 人工评分表）"这一问题被重新提出后，
用户明确决定**仍然不做**。因此本文不是"暂时没做"，而是当前阶段的既定边界：
答卷质量靠人读文件，软件只保证"谁在什么条件下答了什么、多快"这些事实可查、可回溯。

## 理由（Rationale）

- 方案 1 会把「被测模型」与「评委模型」两个变量混在一起：评委本身有偏好与偏差，
  且需要第二份模型加载与显存预算（见 ADR-0015）。
- 方案 2 对自然语言答案几乎必然误判，产出的分数是**假精确**——那比没有分数更危险，
  因为它会被当作对比依据。
- 需求只说「输出一份文件」。加判分意味着新增评分标准（另一份需要维护的知识资产），
  属于范围外扩张。
- 「不判分」也是可回溯的：答卷文件 + 原始 transcript 都在，未来要补判分不必重跑。

## 后果（Consequences）

- 代价：屏幕上的 Scoreboard 里 EXAM 一行只显示「N 份答卷已落盘」而不是分数——
  这是刻意的：**能显示的只有事实**（见 ADR-0016 关于值列的约定）。
- 代价：跨模型对比表只比 bench 与 perplexity，不比答卷质量；答卷质量靠人读文件。
- 后续若要判分，需要新 ADR：定义评分标准来源（标准答案？评委模型？）、评委的显存预算、
  以及评分结果如何进入 `TrialRecord`（新增 `payload` 字段还是新 `TestKind`）。

- `arena/domain.py::AnswerSheet`（无分数字段）
- `arena/runners.py::ExamRunner._build_record`（只抽取正文与吞吐）
- `arena/store.py::AnswerSheetWriter._render`（元数据头 + 正文）
